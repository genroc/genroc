A task is one unit of work in a process definition. Every task has an `id` and a `switch`;
everything else is optional. A task with no `action` is a pure routing task.

## Fields

| Field | Type | Meaning |
|---|---|---|
| `id` | string | Unique task identifier. `end` and `next` are reserved and cannot be used. |
| `action` | object | The action to perform. Omit for switch-only (routing) tasks. |
| `timeout` | duration \| object | Maximum execution time, honoured by `fetch` and `external` tasks. |
| `only_once` | boolean | At-most-once execution. Defaults to `false`. |
| `on_error` | list | Ordered error-routing rules evaluated when the action fails. First match wins. |
| `output` | value | Templated value that remaps this task's output. |
| `switch` | string \| list | **Required.** Where control goes next. |

### `timeout`

Either a duration shorthand — `"30s"`, `"2h30m"`, a bare number of milliseconds, or a `$:`
expression evaluating to milliseconds, all resolved in UTC — or an object naming exactly one
of `for` / `until`, plus an optional `tz`.

`until` is an absolute deadline and is accepted only on an `external` task.

Omit it for no timeout of its own: a `fetch` falls back to the engine default, an `external`
waits indefinitely.

### `only_once`

When `true`, the engine guarantees at-most-once execution:

- Retries are allowed only for `pre.*` codes (the remote was never reached) or for
  `on_error` rules carrying `not_reached: true`.
- A rule that is not restricted to `pre.*` needs `not_reached: true` **and** must name exact
  codes — no wildcards.
- `http.timeout`, `http.disconnected`, `external.timeout`, `external.lost` and `only_once.interrupted` can
  never be retried at all: the request left and nothing came back, so nothing can be
  asserted about it.

An attempt cut short by a crash raises `only_once.interrupted`, which `on_error` can catch —
typically to ask the system of record what happened and then carry on.

### `output`

Evaluated against the context plus `self.result` (the action's raw result) and
`self.previous` (this task's prior output — non-empty when a loop re-enters the task).

When `output` is set, its value is stored as `outputs.<taskID>` and seen by the switch as
`self.output`; the raw result is **not** exported. It is computed only when the action
succeeds.

## `switch`

Scalar shorthand — `"next"`, `"end"`, `"$task-id"` — or an ordered list of cases. `next`
advances to the next task in the list and is invalid on the last one; `end` terminates the
instance.

The last case must be a catch-all, with `case` omitted.

| Key | Meaning |
|---|---|
| `case` | Expression selecting this arm. Omit on the final catch-all. |
| `goto` | Task to route to: `$task-id` or `end`. |
| `raise` | Terminate as `raised`. See [raise and panic](#raise-and-panic). |
| `panic` | Terminate as `failed`. See [raise and panic](#raise-and-panic). |

```yaml
switch:
  - case: "self.output.attempt >= input.max_attempts"
    raise:
      code: poll_timeout
      message: "gave up after max_attempts polls"
  - goto: $check
```

## `on_error`

| Key | Meaning |
|---|---|
| `code` | Patterns matched against the error code. Empty list = catch-all. |
| `retry` | Retry policy applied before the rule routes. Omit for no retries. |
| `goto` | Task to route to when retries are exhausted: `$task-id` or `end`. Omit to fail the instance. |
| `raise` | Terminate as `raised` with this code and message instead of routing. Mutually exclusive with `goto` and `panic`. |
| `panic` | Terminate as `failed` with this code and message instead of routing. Mutually exclusive with `goto` and `raise`. |
| `not_reached` | Assert that this code means the remote call was never reached. |

### Code patterns

`%` is the only wildcard and matches any run of characters. Every other character —
including `_` and `.` — is literal, so `order_%` matches `order_placed` but not
`order.placed`.

Catchable engine codes, reported by an action task's call:

| Code | Raised when |
|---|---|
| `http.NNN` | The response status was not accepted (e.g. `http.500`, `http.202`). |
| `http.timeout` | The request left and no response came back in time. |
| `http.disconnected` | The request left and the connection broke before a response. |
| `pre.error`, `pre.timeout` | The call never reached the remote. |
| `output.parse` | The response body is not valid JSON. |
| `output.too_large` | The response body exceeds the fetch response cap. |
| `output.invalid` | The body does not validate against the schema declared for it. |
| `external.timeout` | An `external` task's deadline passed with no submitted outcome. |
| `external.lost` | A worker's claim on an `only_once` `external` task lapsed with no answer, so the task was not handed out again. |

Internal `engine.*` failures — `engine.spawn`, `engine.collect`, `engine.expression` — are
terminal and are **not** routed through `on_error`.

On a `child`, `child_map` or `child_list` task the codes match the codes the child processes
can **raise**, plus `output.invalid` — a child that completed, but whose output did not
satisfy the `result_schema` this task narrowed it with. Each pattern is checked at
registration against that set. A child that *failed* rather than raised is never catchable;
convert the failure into a raise inside the child.

### The `error` value

A rule that routes with `goto` makes the failure readable at the task it routes to, as
`error`:

| Field | Meaning |
|---|---|
| `error.code` | The code that matched. |
| `error.message` | Human-readable detail. |
| `error.task` | The task that failed. |
| `error.data` | The response body, where the failing fetch declared a schema for that status. |
| `error.child_key`, `error.child_index` | Which child raised, on a batch route. |

**`error` exists only in the task the rule routes to.** The next ordinary transition drops
it, so a task further downstream cannot read it — carry what you need forward by projecting
it into the handler's `output`, the same way every other value travels.

`error.data` is present only where a reaching rule declared a body for the status it catches,
and its type comes from the rule's own `code` patterns. A rule naming one declared status
gets exactly that schema; widening the patterns to statuses nobody described, or to a code
that carries no body at all, widens the type to admit `null`.

```yaml
- id: call
  action:
    type: fetch
    url: "${ config.api }/orders/${ input.id }"
    method: GET
    responses:
      200: { type: object, properties: { state: { type: string } } }
      404: { $ref: "#/$defs/problem" }
  on_error:
    - code: [http.404]
      goto: $missing
  switch: end

- id: missing
  output: { reason: "$: error.data.detail" }
  switch: end
```

### `retry`

A bare attempt count, or an object naming any of `attempts`, `delay`, `factor`, `max_delay`.

```yaml
on_error:
  - code: [http.5%]
    retry: { attempts: 5, delay: "2s", factor: 2, max_delay: "1m" }
    goto: $compensate
```

Not supported on child tasks — retry inside the child, then raise.

### `raise` and `panic`

The same three keys on both clauses, wherever they appear — a `switch` case or an `on_error`
rule. They differ in what they do: a `raise` concludes the instance as `raised`, a condition
a parent may react to by naming the code; a `panic` fails it, and nothing can ever catch one.

| Key | Meaning |
|---|---|
| `code` | A literal `lower_snake_case` name, never an expression — it is what a parent branches on and what `error_code` is filtered by. |
| `message` | Prose, rendered when the clause fires; must produce a non-null string. |
| `data` | Optional structured payload, evaluated in the same scope as the message. |

`data` lands on this instance's own `error.data`, where the instance detail and the logs show
it. Omitting it **clears** that slot rather than leaving behind whatever the rule caught, so a
fault carries only what it says it carries — forward a caught body explicitly when you want it.

A **parent** reads a raise's `data` only where its call declares a shape for that code under
[`raises`](#raises); a panic's reaches an operator and nobody else, since nothing can catch a
panic. A panic's payload also stays on the instance that authored it — ancestors inherit its
code and message, not its data.

```yaml
on_error:
  - code: [http.422]
    raise:
      code: script_threw
      message: "${ error.data.name }: ${ error.data.message }"
      data: "$: error.data"
```

## Action types

| `type` | Required | Result |
|---|---|---|
| `fetch` | `url` | The response body. |
| `child` | `name` | That child's output, unwrapped. |
| `child_map` | `children` | An object keyed by child name. |
| `child_list` | `name`, `over` | An array of the children's outputs, in `over`'s order. |
| `delay` | exactly one of `for` / `until` | — |
| `external` | — | The submitted result. |

### `fetch`

An HTTP call, shaped like `fetch(url, {method, headers, body})`. Every field is an
expression, so the whole request can come from the context.

| Field | Meaning |
|---|---|
| `url` | Request URL. |
| `method` | HTTP method. Defaults to `POST`. |
| `headers` | A value evaluating to a string map. |
| `query` | Query parameters appended to the url. A value evaluating to a map of scalars; a `null` value omits its parameter. |
| `body` | Templated request body, sent raw — an object as JSON. |
| `accepted_status` | Array of status patterns treated as non-errors: `"2xx"`…`"5xx"`, or a 3-digit code. Defaults to any 2xx. |
| `responses` | Status pattern → schema for the body that status carries. |

`X-Genroc-Instance-Id` and `X-Genroc-Task-Id` are stamped on every request authoritatively,
so a caller-supplied header cannot spoof them.

#### `query`

```yaml
query:
  q: "$: input.term"
  page: "$: input.page"    # null omits the parameter entirely
  tag: "$: input.tags"     # an array repeats it: ?tag=a&tag=b
```

Values are URL-encoded, which is the point: interpolating a term into the url escapes
nothing, so one carrying `&`, `=`, `#` or a space corrupts the url or injects a parameter.
A space is sent as `%20`. A value is a scalar, `null`, or an **array of scalars**, which
repeats the parameter once per element in the order given — `?tag=a&tag=b`. An empty array
behaves like `null`: nothing is sent. Elements are escaped individually, so one carrying a
separator cannot add a parameter of its own.
Parameters are **appended**, so a `url` may already carry its own `?a=1`. Values are scalars —
strings, numbers and booleans — and a `null` omits its parameter, so an optional one needs no
conditional. That is deliberately unlike `headers`, where a null is an error.

#### Response metadata

A fetch exposes what the response carried besides its body, as siblings of `self.result` —
the body keeps its meaning, nothing is re-wrapped:

| | |
|---|---|
| `self.status` | the HTTP status, as an integer |
| `self.headers` | the response headers, as a string map |

Both exist only on a `fetch`; no other action type has a status. Header keys are
**lowercased** — Go canonicalises to `Retry-After`, so a canonicalised map would make
`self.headers['retry-after']` silently null — and repeated headers are comma-joined, which
`Set-Cookie` is the casualty of. Any key may be absent, so reading one yields `string | null`.

This is how a definition branches on the status itself rather than routing a healthy response
through `on_error`. Declaring the status in [`responses`](#responses) is all it takes —
a 2xx key accepts that status, so `accepted_status` is not needed here:

```yaml
- id: check
  action:
    type: fetch
    url: "${ config.api }/jobs/${ input.id }"
    method: GET
    responses:
      200: { type: object, properties: { result: { type: string } } }
      202: null                        # 202 is a state, not a failure — and carries no body
  switch:
    - case: "self.status == 202"       # still running
      goto: $wait
    - goto: end
```

Reach for `accepted_status` when `responses` cannot say it: to accept a **non-2xx** status
(a `404` key types `error.data` but never accepts it, so `accepted_status: ["200", "404"]`
is the only spelling), or to compute the set with an expression.

#### `responses`

One map describes the whole endpoint. The status class splits it: a **2xx** key types
`self.result` *and* makes that status accepted; a **non-2xx** key types `error.data` and
leaves the status routing through `on_error` as it would have.

```yaml
responses:
  200: { type: object, properties: { state: { type: string } } }
  202: null                      # accepted, carries no body
  "400, 401": { $ref: "#/$defs/problem" }
  "5xx": { type: object, properties: { trace_id: { type: string } } }
```

A key is a comma-separated list of the same patterns `accepted_status` takes — an exact code
or a hundred-range. Exact beats range, so `{404: A, "4xx": B}` gives a 404 the `A`. Quote a
key that is not a plain number.

| Entry | Means |
|---|---|
| a schema | the status carries a body of that shape |
| `null` | the status carries no body |
| `{}` | the status carries a body of unknown shape — exportable, not readable until a consumer restates it |

**Declaring a 2xx narrows what is accepted.** With `{200: T}` and nothing else, a `201`
raises `http.201`. Widen it with `accepted_status`, or declare the status you expect —
`201: null` accepts it and says it carries no body, which is usually what you meant.

`self.result` is the union of the schemas for the statuses that can be accepted, plus `null`
where an accepted status is described by no key. So `{200: T}` types it as exactly `T`, while
`{200: T, 202: null}` types it as `T | null`. Declare nothing and the result is untyped —
available only as `self.result` in this task's own switch, never exportable.

**A declared schema is enforced.** A body that is empty, unparseable, oversized or does not
conform raises `output.invalid` / `output.parse` / `output.too_large` **instead of** the
status code the response would otherwise have produced — on the error channel too, so
`code: [http.4%]` no longer catches a 400 whose body is malformed. Name both codes to handle
that, or declare `"4xx": {}`, which conforms to anything and never escalates.

### `child`, `child_map`, `child_list`

| Field | On | Meaning |
|---|---|---|
| `name` | `child`, `child_list` | Child process to invoke. |
| `version` | all | Version to run; `0` means the latest published version. |
| `input` | `child`, `child_map` entries | Templated value building the child's input payload. |
| `over` | `child_list` | A `$:` expression evaluating to an array. One child per element, the element being its input. An empty array spawns nothing and yields `[]`. |
| `children` | `child_map` | Keyed map of children run concurrently. Keys become the access names in `outputs.<taskID>`. |
| `result_schema` | all | Validates and exposes the child's output — per element for `child_list`. |
| `raises` | `child`, `child_list`, `child_map` entries, `external` | Raise code → schema for the payload that code's fault carries, or `null` for a code that carries none. On `external` it is also the closed set of submittable codes. |

Declaring a shape where the child left a value untyped (`{}`, the top type) narrows it: the
collected output is conformed against the schema, and undeclared keys are dropped. A child
whose output does not satisfy the declaration reports `output.invalid`, catchable on this
task.

#### `raises`

`result_schema` types what a child returns; `raises` types what its faults carry. The **caller**
declares it, keyed by raise code, which is what lets a shared child stay generic: it attaches a
payload, and each caller says what it expects of it.

```yaml
action:
  type: child
  name: script
  result_schema: { $ref: "#/$defs/reading" }
  raises:
    script_threw:   { $ref: "#/$defs/script_error" }   # typed
    script_timeout: {}                                  # present, narrow it yourself
    script_aborted:                                     # null: declared, carries nothing
    # script_unknown: not declared → error.data is absent for it
on_error:
  - code: [script_threw]
    goto: $classify        # error.data is the declared shape here
```

| Declaration | `error.data` at a rule catching that code |
|---|---|
| a schema | that shape, conformed — undeclared keys dropped |
| `{}` | the top type: present, and narrowed before it can be read |
| `null` | absent — the code is declared, and carries nothing |
| no key | absent |

`null` and no key read the same here; they diverge on an [`external`](#external) task, where
`raises` is the closed set of submittable codes and omitting one means it cannot be sent at
all. A boolean is not accepted in either position — this is a schema slot, and genroc has no
boolean schemas.

A rule whose patterns can also reach a code nothing declares — a wildcard, a catch-all, or
`output.invalid` — widens the type to admit `null`. Each declared code must be one the child
can actually raise; a code it never raises is refused at registration, like an `on_error` rule
for one.

The payload is conformed when the batch resolves. A payload that does not fit — including a
raise that attached none — **replaces** the raised code with `output.invalid`, so a rule naming
the raised code no longer fires and a rule naming `output.invalid` does.

### `delay`

Parks the instance until a duration elapses (`for`) or an instant arrives (`until`), without
holding a worker, then routes via `switch`. Exactly one of the two.

| Field | Accepts |
|---|---|
| `for` | `"2h30m"`, `"1d 12h"` (units `ms`, `s`, `m`, `h`, `d`, `w`, `mo`, `y`), a bare number of milliseconds, or a `$:` expression evaluating to milliseconds. A quoted number without a unit is rejected as ambiguous. |
| `until` | `"2026-09-01T08:00:00+02:00"` (RFC 3339), `"2026-09-01 08:00"` (in `tz`), `"+2d 08:00"`, `"*-*-01 08:00"`, `"mon 09:00"`, `"*:*:00"` (every whole minute; any clock field may be `*` or a base/step — `"*:*:0/5"` is every five seconds), a bare number of unix milliseconds, or a `$:` expression evaluating to unix milliseconds. An instant already past resolves immediately. |
| `tz` | IANA name (`"Europe/Prague"`) or fixed offset (`"+02:00"`). Defaults to UTC. Abbreviations such as `CET` are rejected — they are ambiguous across DST. |

### `external`

Parks the instance until an outside caller submits a result through the external-tasks API.
No worker is held while waiting.

| Field | Meaning |
|---|---|
| `input` | Templated value, snapshotted and exposed to the resolver through the queue — the only context the resolver sees. |
| `result_schema` | Validates the submitted result before the instance resumes. Without it any JSON result is accepted. |
| `raises` | The codes a caller may answer with, each mapped to the payload it carries (or `null` for none). This is a **closed set** — a code outside it is refused. |

An optional task `timeout` raises the catchable `external.timeout`; absent, it waits forever.
This is the one place an absolute `until` deadline is accepted.

#### The error channel

A submission carries one **outcome** — a `result` or an `error`, never both — and the same two
endpoints take either:

| | addressed by | unarmed task |
|---|---|---|
| `POST /api/external-tasks/resolve` | a `token` (from the queue, or from a claim) | rejected — the token names a live arming |
| `POST /api/instances/{id}/signal` | instance id + `task_id` | buffered FIFO until the task next arms |

An `error` is routed through the task's `on_error` rules exactly like a call error:

```jsonc
// POST /api/external-tasks/resolve
{ "token": "…", "result": { "fee": 25 } }          // the success channel
{ "token": "…", "error":  { "code": "limit_exceeded",
                            "message": "over the approval limit",
                            "data": { "limit": 1000 } } }
```

```yaml
- id: price
  action:
    type: external
    input: { amount: "$: input.amount" }
    raises:
      limit_exceeded: { type: object, properties: { limit: { type: number } } }
      worker_crashed:            # declared, carries no data (null)
  on_error:
    - code: [limit_exceeded]
      goto: $over_limit          # error.data.limit is readable here
    - code: ["%"]
      raise: { code: worker_failed, message: "the worker could not price it" }
  switch: [{ goto: end }]
```

**`raises` is the closed set of codes a caller may submit.** A code outside it is refused with
a 400 listing what is accepted, and a task declaring no `raises` has no error channel at all.
This is stricter than a child task, where `raises` only types payloads — and deliberately so:
a child's raisable codes come from its own definition, so a typo in an `on_error` pattern is
already caught at registration, while nothing about an outside caller is knowable until it
submits. Submission is the only place a wrong code can ever be caught.

Each declaration says what the code carries:

| declaration | the caller sends | `error.data` |
|---|---|---|
| `code:` (null) | no `data` — sending one is refused | absent |
| `code: {}` | anything | present, opaque — narrow it in a rule |
| `code: {type: object, …}` | a matching payload | present, typed |

Null rather than a boolean because this is a schema position, and genroc has no boolean
schemas: `true` there is JSON Schema's "any value validates" — the opposite of what it would
mean — so "no payload" is spelled by the absence of a schema.

The payload is conformed **when it is submitted**: a mismatch is rejected at the API, the task
stays parked, and the caller can answer again with a corrected one.

The submitted `code` is an authored code — lower_snake_case, no dots — so a caller cannot
spell an engine code such as `http.500` or `external.timeout` and be caught by a rule written
for the wire.

#### Pulling work: claim, renew, release

`GET /api/external-tasks` lists the queue and `POST /api/external-tasks/resolve` answers it — enough
for a person or a webhook. A **worker fleet** wants the pull half instead, so two of them do
not run the same task:

| | |
|---|---|
| `POST /api/external-tasks/claim` | leases parked tasks to a `worker_id`, oldest park first. Filters by `process` / `version` / `task`, `limit` per batch, `lease_ms` for the visibility timeout (default 30s). |
| `POST /api/external-tasks/renew` | extends this worker's claims. `renewed` reports how many it still held — a worker learns it lost one here rather than when its answer is refused. |
| `POST /api/external-tasks/release` | hands a claim back at once instead of waiting out the lease. |

A claim returns a **three-part token** — `<instance>.<arming>.<grant>` — and that is the only
handle accepted while the claim is live. The two-part token the queue publishes still answers
an *unclaimed* task, so the approval-UI path is untouched, but it cannot answer over a worker
mid-flight. A signal, which carries no handle at all, is buffered rather than delivered while a
claim is live, for the same reason.

Expiry and re-claim are deliberately asymmetric:

- **Expiry writes nothing.** A lapsed claim just makes the row claimable again — so a worker
  that overran its lease and was *never taken over* can still answer. Discarding work already
  done is strictly worse.
- **A re-claim is a new grant**, and voids the previous holder's token. So does a release,
  which is a deliberate hand-back rather than a lapse.

A claim never delays the task's own `timeout`: the deadline is authoritative, and `external.timeout`
fires on time however long a worker holds the task. Tasks already past their deadline are not
offered, since answering them would no longer be accepted.

On an [`only_once`](#only_once) task a lapsed claim is handled differently, because the first
worker may already have done the work: the task is **not** offered again, and the instance
raises the catchable `external.lost` instead. Like `external.timeout` it is unknowable — nothing
came back to interpret — so `not_reached` cannot buy a retry for it; catch it and ask the system
of record what actually happened, exactly as with `only_once.interrupted`.

Either outcome is accepted while the instance is **paused**: a pause suspends execution, not
delivery, and it is consumed when the tree resumes. A failure signalled before the task arms
buffers exactly as a result does. Rejecting it would discard
work the caller has already done — and on an `only_once` task the `external.timeout` that
followed could never be retried.

An answer that reports a failure means the work was reached, so on an `only_once` task a
retry needs `not_reached: true` naming the exact code — the same rule every other
potentially-reached error follows.
