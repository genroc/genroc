## The CLI

Install genctl by running following command in your terminal:

```sh
curl -fsSL https://genroc.org/install.sh | sh -s
```

This will copy the genctl binary to your default user scoped bin location.

## Starting a project

Once you install genctl, you can create your first project with init command (we assume defaults are used):

```sh
genctl init
```

Enter the project folder:

```sh
cd genroc-app
```

Open the project in your editor. With the default options it looks like this:

```
genroc-app/
├─ data/                  # the database, once the server starts
├─ definitions/
│  └─ hello.genroc.yaml    # the example process definition
├─ .genroc                 # genroc configuration
├─ compose.yaml            # docker compose file for starting the server
└─ .gitignore
```

## Editor support

If you use VS Code, we recommend installing [genroc extension](https://marketplace.visualstudio.com/items?itemName=genroc.genroc).
It provides language support for `*.genroc.yaml` files.

## Running with docker

> To continue you need to have [docker installed](https://docs.docker.com/desktop/) on your system.

Following command will start docker containers:

```sh
docker compose up -d
```

Genroc listens on port 8448, which is where genctl looks for it by default, so it should now work:

```
> genctl instances
no instances
```

Should run without an error.

Stop it with `docker compose down`, your data stays in the `data` folder.

> The default setup has no authentication, anyone on your network can run code through it.
> Turn it on with `genctl init --auth` in a new project ([Authentication](../operating/authentication.mdx) for an existing one),
> and see [Running in production](../operating/running-in-production.mdx)
> before running genroc anywhere but your laptop.

## `data` folder

Our example project stores database files in the `data` folder. This folder is in `.gitignore` by default.

Genroc runs as its own user in the container, so `genctl init` makes the folder writable for everyone.
On Linux, a folder Docker creates itself is owned by root and genroc can't write to it, so
to prune the database delete the files, not the folder:

```sh
docker compose down
rm data/genroc.db*
docker compose up -d
```

After a fresh clone of the project on Linux, create the folder with `mkdir -m 777 data`.

## Uninstalling
To uninstall genctl:

```sh
curl -fsSL https://genroc.org/install.sh | sh -s -- --uninstall
```

To also delete your settings (config directory), add `--purge`:

```sh
curl -fsSL https://genroc.org/install.sh | sh -s -- --uninstall --purge
```
