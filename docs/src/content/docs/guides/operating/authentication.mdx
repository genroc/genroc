Authentication is off by default. Turn it on with `--auth` (or `GENROC_AUTH=true`),
then every API request needs a token in the `Authorization` header:

```
Authorization: Bearer genroc_sk_...
```

For `genctl`, store the token once, or set `GENROC_TOKEN`:

```sh
> genctl config set token genroc_sk_...
```

Genroc supports classic tokens and JWT tokens.

## Permissions

Every token carries a list of permissions: `read`, `operate`, `deploy`, `worker` and `admin`.
Any one of them is enough for an endpoint that lists it, and `admin` is enough for everything.
What each permission allows is in the [REST API reference](../../reference/rest-api.mdx#permissions).

## Classic tokens

These are tokens managed by the genroc server. You can create them through the
API or CLI, which needs an admin token.

```sh
> genctl token create --perms read --label "Read only token"

created 9eezcgww  perms=read
  shown once:
genroc_sk_BOdTfRofN1uEUCZnBOzU8Nybuk1Z1BzZnLF2-zdN6ko
```

Genroc stores a SHA-256 hash of the token and the content is only shown once,
so you need to make sure it's safely stored.

## Initialization

The API can't create the first token, because you need a token to call it.
Instead you create the first admin token directly in the database, and use it to create the rest.

### First admin token

Run the `genroc` binary (not `genctl`) against the database. It needs no token
and no running server, only access to the database. If the database doesn't exist
yet, it's created:

```sh
> genroc token create --perms admin --label admin --db genroc.db

created 3kjfx4vm  perms=admin
  shown once:
genroc_sk_EbTqXuTJhseXWTOcZyGlwCD8USE63A8YaZ36F0mmM5s
```

Only the token itself goes to stdout, so `TOKEN=$(genroc token create ...)` captures just the token.

Use `--pg <dsn>` instead of `--db` for PostgreSQL. Both are also read from `GENROC_DB` and
`GENROC_PG`, which the `compose.yaml` from `genctl init` already sets, so with docker it's just:

```sh
docker compose run --rm genroc token create --perms admin --label admin
```

The same command gets you back in if you lose the admin token.
Genroc also warns at startup when there is no admin token (unless JWTs are enabled).

### Seed tokens

Some tokens have to exist before anything starts: a worker that starts together
with genroc, a CI environment that is created from scratch, or a secret
that already lives in your platform's secret manager. For these, give genroc
a file with the tokens and it stores them at startup.

Generate a token. This runs offline, no server or token needed:

```sh
> genctl token generate
genroc_sk_QUbqpu_q9k4fTbCN2J7RRPUYXTzae0mRXcC2CIF_ftY
```

Put it in a file, one token per line as `label=perms=token`.
Separate several permissions with commas, lines starting with `#` are comments:

```
# workers
evaluator=worker=genroc_sk_QUbqpu_q9k4fTbCN2J7RRPUYXTzae0mRXcC2CIF_ftY
ci=deploy,read=genroc_sk_...
```

And point genroc at the file, with the flag or `GENROC_SEED_TOKENS_FILE`:

```sh
genroc --auth --seed-tokens-file ./seed-tokens
```

On every start genroc stores the tokens it doesn't have yet and skips the rest,
so restarting is safe. A revoked token stays revoked, even if it's still in the file.

## JWT tokens

With `--auth` on, genroc can also accept JWTs that someone else mints. Give genroc a shared secret
(at least 32 characters) with `--jwt-secret-file` (or `GENROC_JWT_SECRET_FILE`),
or inline with `GENROC_JWT_SECRET`, and it accepts any HS256 token signed with it.
Genroc UI works this way, but your own service can mint the tokens too.

The token has to carry:

```json
{
  "iss": "genroc-ui",
  "aud": "genroc",
  "sub": "ada@example.com",
  "perms": ["deploy", "operate", "read"],
  "exp": 1788000060
}
```

`perms` are the same [permissions](#permissions) as for genroc tokens, `sub` is who is calling
and shows up in logs as `jwt:ada@example.com`. `exp` is required, so keep the tokens short-lived.
`iss` and `aud` default to the values above, change them with `--jwt-issuer` and `--jwt-audience`.

Genroc tokens keep working beside JWTs, so people can come through the UI
while `genctl` and workers use their genroc tokens. A secret without `--auth`
is refused at startup.

Genroc reads the secret only at startup. To rotate it, replace it and restart genroc together with
whatever mints the tokens; a token signed with the old secret stops verifying
([rotating it with Genroc UI](./genroc-ui.mdx#rotating-the-secret)).

> Anyone with the secret can mint a token with any permissions, so keep it as safe as an admin token.
