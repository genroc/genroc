You might be wandering what happens when a fetch action fails? Let's look at that.

```genroc
  - id: load_user
    action:
      type: fetch
      method: get
      url: "https://api.example.com/users/${input.user_id}"
      responses:
        200:
          type: object
          properties:
            email: { type: string }
            activated: { type: boolean }
          required: [email, activated]
        409:
          type: object
          properties:
            user_is_protected: { type: boolean }
    on_error:
      - code: ["http.404"]
        raise:
          code: "user_doesn_exist"
          message: "user ${input.user_id} doesn't exist"
      - code: ["http.409"]
        case: "error.data.user_is_protected == true"
        goto: $user-user-protected
      - code: ["pre.%", "http.timeout", "http.disconnected", "http.503"]
        retry: 3
    switch: next
```

Your main tool is the `on_error` field. You can match one or multiple errors
with the `code` field and you can also use `%` wildcard to match multiple errors at once.

Errors are sorted into families by their prefix:

| Code | Means |
|---|---|
| `http.<status>` | a status `accepted_status` did not admit, e.g. `http.404` |
| `http.timeout` | connected, but no response arrived in time |
| `http.disconnected` | the request went out, the connection broke before a response |
| `pre.timeout` | timed out before the request was written — it never left |
| `pre.error` | failed before the request was written — it never left |
| `output.parse` | the response body was not valid JSON |
| `output.too_large` | the response body exceeded the size a fetch will read |
| `output.invalid` | the result did not satisfy the schema declared for it |
