To make our process actually do something, we need a way how to communicate with
outside world and that is where the task `action` comes in.

## Action

Let's say we want to send our users email two ours after registration and welcome
them.

```genroc
name: welcome-user
input_schema:
  type: object
  properties:
    user_email:
      type: string
  required: [user_email]

tasks:
  - id: wait-some-time
    action:
      type: delay    # process will be parked for 2 hours
      for: 2h
    switch: next

  - id: welcome
    action:
      type: fetch    # this will hit endpoint on our API
      url: "https://api.example.com/emails"
      method: post
      body:
        # passing data from input to the request body
        to: "$: input.user_email"
        template: welcome-after-registration
    switch: end
```

In the example above we've used `delay` and `fetch` actions.
The delay will park the action for specified amount of time, while it waits there is no active thread anywhere, it just sits in the db.

The fetch action will then hit the specified endpoint. We are sending body with parameters which can be either expressions or static data.

## Reading result of the fetch

What if instead of sending data, you want to read data? No problem, let's look at another example.

```genroc
  - id: load_user
    action:
      type: fetch
      method: get
      url: "https://api.example.com/users/${input.user_id}"
      responses:
        200:
          type: object
          properties:
            email: { type: string }
            activated: { type: boolean }
          required: [email, activated]
    switch:
      - case: "self.result.activated == true"
        goto: end
      - goto: $nudge
    # mapping the task output (what parts of the response we need)
    output:
      email: "$: self.result.email"
```

To read the output of fetch, you need to specify it's response type.
Genroc will validate the data against the schema, so no invalid data will ever get in.

Result of the fetch is then available as `self.result` in the `case` expression,
so we can check if the account is activated or not.

`self.result` is only usable within the same task. If we want to use some data later (in following tasks),
we have to map it through output. In this case we are producing output `{ email: '<user email>'}` which will then
be available to following tasks under `outputs.<task-id>`.

## Expressions

Genroc supports expressions which allow you to dynamically evaluate or pass from one task to another.
In the expressions you can reference following variables:

  - `input` - process input defined by `input_schema`
  - `outputs.<task-id>` - output of the previous task (if defined)
  - `self` - data about current task not available outside of it

You can also use basic operators like `==`, `!=`, `<`, `<=`, `>`, `>=`.

Expressions can also compose objects or arrays:

```genroc
{name: "John"}        # returns object
["John", "Marie"]     # returns array
```

### String template

This is a simle usecase which allows you to dynamically compose string value.

```genroc
"https://api.example.com/users/${input.user_id}"
```

The value passed to to the template must not be primitive value and not null.

You can escape `${}` by doubling the `$`, e.g.:

```genroc
"https://api.example.com/users/$${input.user_id}"
```

### Expression of any type

By prefixing the string with "$: " you are not creating a template, but the whole expression result is
used and it's type is honored:

```genroc
"$: self.result.email"
```

This way you can also return whole objects e.g.:

```genroc
"$: self.result"
```

This would result in object of `{ email: "..." }`.

### Raw expressions

In `switch/case` fields there is no possibility to use static values, so there is no `$:` or `${}` syntax only the expression directly:

```genroc
switch:
  - case: "self.result.activated == true"
    goto: ...
```

The same syntax is used also for `error/case` fields which we will discuss later.


## Shapes

Shapes are a way how to conveniently shape the data. Best example is the task `output` field.

### Fully static

Shape can be fully static in yaml, no expressions at all.

```genroc
output:
  ok: true
```

### Combined

Define the object shape statically and only pass resulting values dynamically.

```genroc
output:
  ok: "$: result.is_ok"
```

### Expression only

Because you can define objects in expressions, 
you can define the full structure in the expression or pass a variable which has the expected shape.

```genroc
output: "$: { ok: result.is_ok }"
```

## Slots

You can combine shapes/expressions anywhere where a dynamic value is expected.
In the examples above that is:

| Slot | Where | Syntax |
|---|---|---|
| `url`, `method` | `fetch` action | string template |
| `body` | `fetch` action | shape |
| `for` | `delay` action | literal duration, or a `$:` yielding integer * |
| `case` | `switch` | raw expression |
| `output` | `task` | shape |

> \* `for` can contain human readable syntax e.g. `2h30s` for static strings, dynamic value can only specify milliseconds as number

Every action and clause introduced later brings its own slots, but the syntax is always one of these.
